# 평가·검증 결과 (2026-10-30)

발표 자료용 숫자와 그 근거를 모아 둔 문서예요. 데이터 받는 법·재현 명령은 [README](../README.md) "데이터"에 있어요.
**LLM(코디세이 게이트웨이) 칸은 아직 재지 않았어요**(호출 횟수를 먼저 알리고 `--engines rule,llm,hybrid`로 잴 예정).

## 1. 판단 방식 비교

| 시험지 | 키워드 규칙 (사기 잡음 / 정상 오탐) | 가벼운 모델, 폰 안 (사기 잡음 / 정상 오탐) |
|---|---|---|
| Korean_message 평가용 1,548개 (학습에 안 쓴 10%) | 67% / 4% | **99% / 0%** |
| KR-MOB-SMISHING v1 104개 (정상 = 공식 안내) | 100% / 6% ※ 보낸 번호 종류 사용 | 95% / 100% |
| 직접 쓴 예시 55개 (규칙을 다듬은 문자라 발표용 아님) | 100% / 0% | 76% / 50% |

읽는 법
- **내용만 보면 공식 안내와 사기를 구분할 수 없다**: KR-MOB의 정상 문자는 진짜 공식 안내인데 사기와 똑같이 링크·"즉시 확인"을 쓴다.
  키워드 규칙도 내용만 보면 오탐 100%였다 → **보낸 번호 종류**(대표번호 15xx vs 개인 010)를 함께 보니 6%.
  (합성 데이터라 정상 = 전부 대표번호 → 실제보다 효과가 크게 보일 수 있음)
- **가벼운 모델은 같은 성격의 문자에는 강하지만 다른 문체에는 약하다**: 학습 데이터의 정상 문자가 일상 대화라
  공식 안내 문체를 다 사기로 본다 → 최종 판정이 아니라 **폰 1차 필터**로 쓴다.
- 키워드 규칙이 놓친 사기는 대부분 **글자를 비튼 도박 광고**("카지눠", "Cbt⑦⑦.com") → 학습 모델이 필요한 이유.

## 2. 폰 1차 필터 (개인정보: 평범한 문자는 폰 밖으로 안 나간다)

규칙: 위험 단어(안내 단어 포함) OR 링크 OR 가벼운 모델 점수 ≥ 0.3 → 서버로. 진짜 자녀 번호면 '엄마'·'아빠'만으로는 안 보냄.

| 시험지 | 사기 문자 서버로 | 평범·안내 문자 폰에 남음 (규칙만 → 규칙 + 모델) |
|---|---|---|
| Korean_message 평가용 | **730/730 (100%)** | 0% → **70%** |
| KR-MOB | 73/73 (100%) | 0% → 0% (공식 안내는 서버에서 설명) |
| 직접 쓴 55개 | 33/33 (100%) | 14% → 18% |

- 세 시험지 모두 **사기 문자를 하나도 놓치지 않았다**.
- 모델: 문자 2~3글자 조각(해싱 65,536칸) + 로지스틱 회귀, 64KB, 학습 2초, 판단 1ms 미만. 파이썬·안드로이드·웹이 같은 점수(고정 예시 12개, 차이 1e-9 미만).
